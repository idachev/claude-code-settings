# .claude

My personal [Claude Code](https://docs.claude.com/en/docs/claude-code) configuration — global instructions, settings, and skills.

This is a snapshot of `~/.claude` minus runtime state, conversation history, and credentials (see `.gitignore`).

## Clone and set up

This repo *is* the config directory, so clone it as `~/.claude`:

```bash
git clone git@github.com:idachev/claude-code-settings.git ~/.claude
cd ~/.claude
scripts/install-hooks.sh
```

If `~/.claude` already exists (Claude Code creates it on first run), clone elsewhere and
copy the tracked files in, or `git init` in place and add this as a remote — don't move
the directory out from under a running session.

`scripts/install-hooks.sh` is **required, not optional** — git cannot version the
filters and hooks this repo depends on, so they have to be installed once per clone.
See [How the git plumbing works](#how-the-git-plumbing-works).

Then, in rough order of importance:

1. **Prune `settings.json`** — the hooks, plugins, and permission settings are mine;
   see [Heads-up](#heads-up-before-copying-my-settingsjson).
2. **Restore the MCP servers.** They are recorded in `.claude-git.json` but are *not*
   applied by cloning, because the file Claude Code reads them from is deliberately
   untracked. Re-add them through the CLI, which writes to the live config for you:
   ```bash
   claude mcp add --scope user headroom -- headroom mcp serve
   claude mcp add --scope user serena -- uvx --from git+https://github.com/oraios/serena \
     serena start-mcp-server --project-from-cwd --context claude-code \
     --open-web-dashboard False
   ```
   Check the result with `claude mcp list`.
3. **Install the `~/.agents` skills** so the `skills/` symlinks resolve — see
   [Replicating the `~/.agents` skills](#replicating-the-agents-skills).

## Heads-up before copying my `settings.json`

A few settings here suit my workflow but may not suit yours:

- `"skipDangerousModePermissionPrompt": true` and `"skipAutoPermissionPrompt": true` disable some permission prompts. Only keep these if you understand what they mean.
- The hook and status-line commands reference things that are **not in this repo**:
  - `~/bin/claude-input-notify.sh` (Notification hook) and `~/bin/claude-statusline.sh`
    (status line) — both live in my
    [own-debian-configs](https://github.com/idachev/own-debian-configs) repo
  - `rtk hook claude` (PreToolUse hook) — from [RTK](https://github.com/rtk-ai/rtk)

  Remove or replace these before using the config, or Claude Code will fail when the hooks fire.
- The `enabledPlugins` list reflects my marketplaces (including private ones like `sc-marketplace`). You'll want to prune to what you actually have access to.

## Replicating the `~/.agents` skills

The three symlinks under `skills/` (`agent-browser`, `find-skills`, `skill-creator`) point at `~/.agents/skills/<name>/`. That directory is managed by the [`skills` CLI](https://github.com/vercel-labs/skills) from Vercel Labs — a multi-agent skills installer that shares a single skill set across Claude Code, Codex, Cursor, OpenCode, and others.

To replicate my install:

```bash
# Installs the agent-browser SKILL + bundled skill-creator
npx skills add vercel-labs/agent-browser

# Installs find-skills (lives in the vercel-labs/skills repo)
npx skills add vercel-labs/skills
```

The CLI writes everything to `~/.agents/skills/<name>/` and tracks versions in `~/.agents/.skill-lock.json`. After install, the symlinks in this repo will resolve correctly.

To verify what got installed:

```bash
cat ~/.agents/.skill-lock.json
ls ~/.agents/skills/
```

## How the git plumbing works

Claude Code rewrites its own configuration while it runs, and some of what it writes
must never land in a public repo. Two mechanisms handle that, both installed by
`scripts/install-hooks.sh`:

**`settings.json` is tracked, and stripped on its way to the index.** A git *clean*
filter (`scripts/git-clean-json.py`, wired up in `.gitattributes`) drops the `autoMode`
key, whose "environment" learning accumulates an inventory of whatever org
infrastructure Claude has seen — cluster names, buckets, protected branches, CI secret
names. The working file keeps everything; only the staged copy is stripped. A clone
*without* the filter commits the file unchanged, which is exactly the accident the
installer prevents.

**`.claude.json` is not tracked at all.** Claude Code owns that file: it holds the OAuth
session, machine and user identifiers, and an entry for every local project, and it gets
rewritten every few seconds. Tracking it meant the committed copy was a stripped-down
stub — and any `git checkout`, `reset`, or `stash` would write that stub straight back
over the live config. So the file is gitignored, and a `pre-commit` hook snapshots just
the versionable slice into **`.claude-git.json`** using
`scripts/sync-claude-git-json.py`. Today that slice is the `mcpServers` block; widen
`KEEP` in the script to version more.

Which file is "live" is easy to get wrong, so it's worth stating: it is
**`~/.claude.json`, in the home directory** — *not* inside `~/.claude`. Setting
`$CLAUDE_CONFIG_DIR` moves it to `$CLAUDE_CONFIG_DIR/.claude.json` (that's how a second,
fully separate Claude Code install works). `scripts/install-hooks.sh` applies that rule
automatically, or takes an explicit path as its first argument.

Consequences worth remembering:

- Committing refreshes `.claude-git.json` automatically. Editing it by hand accomplishes
  nothing — the hook overwrites it from the live config on the next commit.
- To version a new key, add it to `KEEP` in `scripts/sync-claude-git-json.py`.
- Because hooks and filters live under `.git/`, they cannot be versioned. That is the
  one manual step after cloning, and re-running the installer is always safe.

## What's deliberately gitignored

Anything that would leak credentials, conversation content, or machine-local state:

- `.credentials.json` — OAuth tokens
- `.claude.json` — live Claude Code state: OAuth session, machine/user identifiers, and an
  entry for every local project. Its versionable slice is snapshotted to `.claude-git.json`
- `history.jsonl`, `projects/`, `sessions/`, `todos/`, `tasks/`, `shell-snapshots/`, `file-history/`, `paste-cache/` — conversation and session state
- `logs/`, `telemetry/`, `usage-data/`, `statsig/`, `stats-cache.json` — telemetry
- `plans/` — private project notes
- `plugins/`, `cache/`, `backups/`, `downloads/`, `ide/` — reproducible / machine-local

See `.gitignore` for the full list.
